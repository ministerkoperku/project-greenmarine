# Android ARM64 delivery evidence

Scope: GreenMarine 0.8.1 Fabric/Minecraft 26.3, Java 25. Requested launcher:
Zalith; requested device: Poco F8 Pro. No installed game or launcher files
were changed. Game-session acceptance in Zalith remains outstanding.

## Confirmed baseline failures

- `./gradlew test build`: missing `glslangValidator`. Installed the build tool.
- With shader compilation excluded, 161/162 Java tests passed; the bundled
  native FFM test failed because the loader rejected ARM64.
- ELF inspection found a host ARM64 library packaged as `native/linux-x86_64`.
- Running the existing native FFM smoke on Android/Bionic Java 25 printed
  success but exited 139 after scoped library unloading. Linux exited zero.
  An experiment retaining the library in the global arena exited zero.
- Replacing just the explicit droppable Rust error TLS with a fixed buffer
  did not cure the Bionic crash; that experimental source change was reverted.
- Initially pinning the Android lookup globally left retained tracer downcalls
  callable after engine close. A new packaged-library smoke detected this.
  Rebinding symbol addresses to the engine's closeable arena fixed it.
- Python verifier tests initially lacked ImageMagick. After installing this
  documented test tool, the full suite passed.

## Final changes

- Platform resource keys distinguish Android Bionic ARM64, Linux glibc ARM64
  and Linux glibc x86_64. Process libc takes precedence over Android hints.
- Cargo target triples determine bundle destinations. Android can be included
  alongside the host target; stale output directories are removed on switches.
- On Android, code mappings survive until process exit; engine lifetime,
  downcall validity, GPU detach and extracted-file cleanup remain closeable.
  Linux retains scoped unloading. Rust source and all native ABI versions
  remain unchanged.
- Added pause-menu touch settings with parent navigation; F6 remains available.
- Added native platform regression cases, packaged-library smoke and a native
  worker teardown check. No test probes are packaged in the mod JAR.

## Verification

Build command used on the ARM64 Linux/proot development host:

```sh
CARGO_TARGET_AARCH64_LINUX_ANDROID_RUSTFLAGS='-C link-arg=-fno-termux-rpath' \
./gradlew test build -PandroidNative=true \
  -PandroidLinker=/data/data/com.termux/files/usr/bin/aarch64-linux-android-clang
```

- Build successful; Java: **166 tests, zero failures/errors**.
- `cargo test --locked`: **10 passed**, four explicit RX 9070 XT GPU tests
  ignored. `cargo build --release --locked`: successful.
- `python3 -m unittest discover -s tools -p 'test_*.py'`: **45 passed**.
- Unsupported `nativeTarget` is rejected explicitly at configuration.
- Android library LOAD segment alignment: `0x4000` (16 KB).
- Android dynamic dependencies: `libdl.so`, `libm.so`, `libc.so`.
  No Termux RUNPATH/RPATH remains in the final library.
- Actual Android/Bionic OpenJDK **25.0.4**: `NativeRayTracerSmoke` passed
  22 checks plus library lifetime/worker teardown, **exit 0**.
- Same runtime, classpath containing the distribution JAR:
  `BundledNativeSmoke` reported `Native ABI 1 ready [android-aarch64]`,
  sampled successfully, closed cleanly and rejected retained tracer downcalls,
  **exit 0**.
- Linux/glibc JVM: both native smokes passed with **exit 0**; the packaged
  loader selected `linux-aarch64`.
- Android/Bionic Java 25 with `-Dgreenmarine.native.disable=true`: packaged
  native-disabled check and Java pulse fallback passed, **exit 0**.

The Bionic JDK was extracted into an ignored local test directory from the
official Termux `openjdk-25_25.0.4_aarch64.deb`; no existing Java runtime was
replaced. Package SHA-256:
`5bf5914032a9903353d32f0ebb01f38261ba8e1bf5cede89248d81a576318f55`.

To repeat the Java native smokes, compile `engine/tests/*.java` with Java 25
against `build/classes/java/main`. Run `NativeRayTracerSmoke` with the matching
native `.so` path. Run `BundledNativeSmoke` with the distribution JAR and test
classes on the classpath. Both require `--enable-native-access=ALL-UNNAMED`.
The latter also accepts `-Dgreenmarine.native.disable=true` for Java fallback.

## Scope of evidence

These are build, ABI, platform selection and lifecycle checks on actual Bionic
processes, not a rendered Minecraft session. They do not validate the launcher's
SDL/LWJGL/Renderpearl integration, GPU rendering, RT feature availability,
touch layout, foreground recovery or sustained performance. ADB listed no
connected device and Android denied access to the launcher's private data.
Follow `docs/ANDROID-ZALITH.md` for the remaining gameplay acceptance.
